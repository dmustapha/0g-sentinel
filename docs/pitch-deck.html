Sentinel ProofLock

Admission should be provable.

Provable, drift-aware admission for AI agents. An agent is admitted only if a fresh, hardware-TEE-attested risk verdict about its exact on-chain identity is sealed on 0G, and access is revoked the moment its identity drifts.

Live: sentinel-prooflock.vercel.app

The problem

"Trusted agent" is a claim, not a proof.

Consumers accept an agent because a list said it was safe, or because it looked fine last week. None of that binds to the agent's current on-chain identity.

  • Verdicts are stale. A safety check made in the past says nothing about the code and identity running now.
  • Verdicts float free of identity. A rating attached to a name, not to a specific subject, registration digest, and runtime commitment, is easy to spoof and easy to drift out of.
  • Nothing revokes. When an agent rotates its card or changes its subject, downstream consumers keep trusting it.

ProofLock does not certify that an agent is universally safe. It proves one thing precisely: this exact identity satisfied a disclosed policy, the evidence is sealed and re-verifiable, and admission fails closed the instant that identity moves.

How it works

The admission chain.

One evaluation binds identity to attested evidence, seals it on 0G, and turns it into a pure-view gate decision that a consumer can act on.

01
Identity
Resolve an ERC-8004 Agent ID from the canonical Identity Registry. Bind owner, agent wallet, registration digest, source block, runtime commitment.
02
Checks
Typed deterministic checks plus AI-assisted purposes. Subject and its delegation targets are analyzed before any paid step.
03
Compute
Inference through a hardware-TEE 0G Compute provider with a separated enclave signer. Response bound to exact bytes; SDK settlement verifies on-chain.
04
Storage
The canonical evidence envelope is uploaded to 0G Storage, root recomputed locally, finalized Flow tx confirmed, bytes retrieved and re-matched.
05
Lease
A versioned ProofLock lease is written to SentinelRegistryV2 (append-only) and read back.
06
Gate
AgentGateV2.checkAgent returns a stable reason code. ProofLockConsumerDemo.acceptAgent only accepts a subject the gate allows.
  • Drift fails closed. If the registration digest, subject, or runtime code changes, the gate returns DRIFTED / SUBJECT_CHANGED / RUNTIME_CODE_DRIFT and the consumer reverts.
  • Reseal restores access. A fresh evaluation creates a new version; access returns only after the complete policy succeeds again.

Honest limitations

What we do not claim.

Disclosed scope, not silent omission.

  • Request digest is the proxy view. The request commitment is the enclave's normalized (proxy) view, not our raw POST bytes, because the provider proxies to OpenRouter. The response stays bound to exact bytes. requestBytesExact false is expected and benign here.
  • No network availability proof. Storage networkProofVerified is false by design. Retrieval and merkle inclusion are verified; we do not claim an independent network availability proof.
  • Recent activity, not full history. The proof reader surfaces recent finalized activity. A complete historical indexer and backfill is a documented deferral.
  • Admission is scoped. ProofLock does not certify universal safety. Admission means this identity satisfied this deployment's disclosed policy at read time, and only a current lease plus an AgentGateV2 ALLOWED decision admits a consumer action.
